# 驗收與提交

## 本機驗收

全組共同進行整合測試，每位組員按自己的講解文檔準備示範。在本機啟動 TaskFlow 後，使用自行註冊的測試帳戶檢查下列項目。 [六人分工及講解文檔](../README.zh-Hant.md#小組資料) · [本機啟動指引](./setup.md) · [cURL 示範](../README.zh-Hant.md#curl-示範)

| 測試 | 預期結果 |
| --- | --- |
| 未登入訪問 `/tasks` 或任務 API | 網頁轉到登入頁，API 回傳 `401` |
| 輸入錯誤密碼、登入後登出 | 錯誤密碼不能登入，登出後使用舊 Cookie 回傳 `401` |
| 在另一個瀏覽器重設已登入的測試帳戶密碼 | 返回登入頁並顯示重設成功。舊密碼及舊 Session 均失效，新密碼可登入並存取原有任務 |
| 以測試資料核對重設表單。名稱不存在、密碼不符規則、兩次輸入不同 | 分別回傳 `404`、`400`、`400`。原有密碼仍可登入。 |
| 核對 API 寫入限制 | 寫入請求標示跨來源時回傳 `403`。`POST` 或 `PUT` 的內容類型不符時回傳 `415`。 |
| 在同一個 Bash 以示範帳戶登入，再逐句執行四條 cURL | 登入回傳 Cookie。新增、讀取、更新、刪除依次成功，四行 JSON 對應同一筆任務，登出回傳 `204`。 [示範指令](./TaskFlow-curl-demo.txt) |
| 新增、編輯、完成、重新開啟及刪除任務 | 列表可在未完成及已完成之間切換，取消刪除會保留任務 |
| 空白或過長標題、無效日期、錯誤狀態 | 顯示錯誤，資料不會被儲存 |
| 標題含 `<`、`>` 或 `&` | 顯示為文字 |
| 使用自行註冊的第二個帳戶查看第一個帳戶的任務或提交其 ID | 列表看不到另一個帳戶的任務，直接操作回傳 `404` |
| 任務截止日期 | 截止日已過且尚未完成的任務顯示逾期 |
| 停止並重建容器 | 已有帳戶與任務保留，未過期的登入仍有效 |
| Chrome、Edge，375px／1366px 寬度 | 表單和任務操作可用，鍵盤可完成密碼重設並操作按鈕 |

## Cloud Run 上線驗收

由組員 6 記錄驗收的 Cloud Run 版本及 HTTPS 網址，並與組員 2 核對重設密碼的上線條件。 [Cloud Run 部署指引](./member-06-cloud-run-deployment.md) · [組員 2 講解文檔](./member-02-registration-password-reset.md)

1. 在受限存取的 Cloud Run 服務確認版本已就緒。查看啟動日誌，核對應用程式可以接收請求及連接 Atlas。
2. 開放公開存取前，在合併版本驗證帳戶持有人可完成重設，缺少有效身分驗證的請求會被拒絕，成功重設後舊密碼和舊 Session 均失效。
3. 開放後，用無痕視窗直接開啟 `run.app` HTTPS 網址。註冊測試帳戶、登入、新增及編輯任務，再登出。登出後開啟 `/tasks` 應回到登入頁。
4. 使用同一 Atlas 資料庫及 Session 密鑰部署新版本，再確認原有測試帳戶及任務仍可使用。將 README 的 `BASE` 指向公開網址，執行 cURL 示範並核對回應。

## ZIP 打包

1. 將專案檔案複製到 `comp3810sef_groupNo` 資料夾，以實際組別替換 `No`，再壓縮為同名 `.zip`。
2. 保留程式、`package.json`、`package-lock.json`、Docker 設定、`README.md`、`README.zh-Hant.md`、`.env.example` 及整個 `docs/` 資料夾。排除 `node_modules`、實際使用的 `.env`、`.git`、`.agents`、`.aws`、`.codex`、`.playwright-cli` 及測試輸出。
3. 解壓後確認 ZIP 內的頂層資料夾名稱正確，README 的文件連結可開啟，並可按啟動指引設定 `.env` 和啟動專案。 [啟動指引](./setup.md)
